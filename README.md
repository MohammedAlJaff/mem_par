# Equivalent in Principle, Unequal in Practice

**How target parameterization shapes memorization and generalization in diffusion and flow-based models**

This repository is the paper repo for the NeurIPS submission on how `x`, `eps`,
and `v` parameterizations behave differently in practice even when the
underlying diffusion or flow-matching setup is held fixed.

The repo now has five clear surfaces:

- `experiments/`
  live first-party paper workflows
- `src/`
  reusable first-party kernel code
- `baselines/` and `third_party/`
  preserved external comparison code
- `prototyping/`
  scratch and fallback scientific code
- `archives/`
  legacy zip snapshots of older live trees

## Primary Entry Point

The first polished live study surface is `experiments/mnist/`.

Start there if you want the reviewer-facing walkthrough:

```bash
jupyter lab experiments/mnist/mnist_walkthrough.ipynb
```

That notebook is intentionally pedagogical, but it is no longer just an
in-memory demo. It now builds the balanced MNIST subsets line by line, launches
the real saved-run training and checkpoint evaluation path, and then reads the
written artifacts back from disk for plotting and inspection.

For synthetic data sanity checks before training, use:

```bash
jupyter lab experiments/synthetic/gmm_data_sanity.ipynb
```

That notebook checks the canonical GMM/subspace generator in three data-only
settings: a true 2D GMM, a projected high-dimensional GMM, and a fixed `d/D`
sweep where intrinsic dimension increases with ambient dimension.

## Official Saved-Run Path

For the canonical artifact-writing path, run the MNIST study module:

```bash
python -m experiments.mnist.run --download --device cpu
```

If you are running directly from a checkout that has not been installed in
editable mode yet, use:

```bash
PYTHONPATH=src python -m experiments.mnist.run --download --device cpu
```

This writes a full experiment/run/seed/attempt artifact tree under
`tmp/mnist_study/` with:

- saved config snapshots
- experiment/run/seed manifests and per-attempt status metadata
- checkpoints
- training history
- checkpoint evaluation memorization metrics
- batching metadata for the selected `N` and `training.batch_cap`
- readable `logs/attempt.log` output for SLURM/debugging
- scalar figures under the attempt-local `figures/` directory

The standard scalar figures are generated by the core pipeline:

- `training_loss_vs_step.png`
- `f_mem_vs_tau.png`
- `nn_ratio_vs_tau.png`

The MNIST CLI also exposes optional offline-first Weights & Biases tracking:

```bash
PYTHONPATH=src python -m experiments.mnist.run \
  --download \
  --device cuda \
  --wandb \
  --wandb_mode offline
```

When W&B is enabled, one W&B run corresponds to one attempt. By default the
project is derived from the dataset+model combo, such as `memparam-mnist-unet`,
and the visible run name includes dataset, model, `N`, batch cap,
prediction/loss parameterization, training steps, and seed. The default W&B
group is dataset+model+training steps, so `x`, `eps`, `v`, batch-size, seed, and
`N` sweeps stay together inside one dataset/model project. Image runners use
the clean public dataset key, so `flowers --image_size 128` logs under
`memparam-flowers-unet`.
Pass `--wandb_project`, `--wandb_name`, or `--wandb_group` to override these
values explicitly. Local offline files are stored under the attempt's
`logs/wandb/` directory for later `wandb sync`.

## Setup

The repo-level environment target is Python 3.10.

```bash
mamba env create -n mem_param_env -f environment.yml
mamba activate mem_param_env
python -m pip install -r requirements.txt
```

`requirements.txt` installs the project in editable mode and pulls in the
supporting evaluation, notebook, and baseline packages used by the current
stack.

### GPU PyTorch on clusters

`environment.yml` intentionally leaves the PyTorch build choice to the machine.

For NVIDIA Linux clusters:

```bash
CONDA_OVERRIDE_CUDA=11.8 mamba install -y -c conda-forge "pytorch==2.5.1=cuda*" "torchvision=*=cuda*"
python -m pip install -r requirements.txt
```

For CPU-only Linux or Apple Silicon:

```bash
python -m pip install -r requirements.txt
```

## Repo Roles

- `experiments/` is where runnable paper studies now live.
- `src/` stays study-agnostic and reusable.
- `prototyping/gdfm_components.py` remains the fallback reference
  implementation while canonical GDFM hardens in `src/gdfm/core.py`.
- `archives/legacy_experiments_20260416.zip` and
  `archives/legacy_reference_20260416.zip` preserve earlier live trees for
  historical context only.

If something from the legacy material is needed again, bring back the minimum
required implementation deliberately instead of importing from archived paths.
